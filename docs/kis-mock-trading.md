# KIS 모의투자 주문 (2단계 — 가짜 돈, 진짜 주문 API)

AI 가 주문을 **제안**하고, 관리자(나)가 **2단계 코드로 승인한 매수만** 장중에 **조건이 맞을 때** 한국투자증권 **모의투자 서버**(가상 자금)로 나갑니다.
위험을 줄이는 일 — **손절가 도달 매도 · 급변 때 매수 취소** — 는 승인 없이 자동으로 하고 휴대폰으로 알립니다 (사용자 결정 2026-11-26).
실거래 서버로는 코드에서 주문이 막혀 있습니다.

**왜 이렇게 나눴나**: '무엇을 살지'는 하루 한 번 (AI 가 일봉으로 '다음 날 오를까'를 예측하도록 만들고 검증됨 — 장중에 여러 번 다시 돌려도 새 판단이 안 나오고,
하루에 여러 번 사고팔면 세금·수수료(왕복 약 0.2~0.3%)가 쌓임). 대신 '언제·얼마에 살지'와 '빠질지'는 장중 실시간으로 봅니다.

## 1. 준비 (한 번)
1. 한국투자증권 앱·홈페이지에서 **모의투자 신청** → 모의투자 계좌번호 받기 (예: `50123456-01`)
2. KIS Developers(apiportal.koreainvestment.com) → 내 앱 → **모의투자용 앱키·시크릿** 발급
3. `backend/.env` 에 추가 (클라우드 서버면 서버의 `backend/.env`):
   ```
   KIS_MOCK_APP_KEY=모의투자 앱키
   KIS_MOCK_APP_SECRET=모의투자 시크릿
   KIS_MOCK_ACCOUNT_NO=50123456-01
   ```
   - 시세용 키(`KIS_APP_KEY`)는 그대로 둡니다. 시세는 지금처럼 그 키로, 주문만 모의투자 키로 합니다.
   - `KIS_IS_REAL=false`(시세용 키가 이미 모의투자 키)면 위 세 줄을 비워 둬도 그 키·계좌로 주문합니다.
   - 키는 채팅·메신저·git 에 올리지 말고 `.env` 에만 넣으세요.
4. 서버 다시 켜기 (직접 설치: `start.bat` 다시 / Docker: `start-docker.bat` / 클라우드: `bash deploy/update.sh`)
5. 관리자 계정으로 로그인 → 왼쪽 메뉴 맨 아래 **관리자 전용 → KIS 모의투자 주문** → 잔고가 보이면 연결 완료

## 1-1. 휴대폰 알림 (ntfy — 날씨 알림과 같은 앱)
제안이 생기거나 체결·막힘·정지가 되면 휴대폰으로 푸시가 옵니다 (메일은 제안·정지만).
1. 휴대폰 **ntfy 앱**(날씨 알림에 쓰는 그 앱) → **+ (구독 추가)** → 새 주제 이름 입력
   - 날씨 주제와 **다른 이름**으로 새로 만드세요 — 알림이 섞이지 않고, 주식 알림만 따로 끄거나 소리를 바꿀 수 있습니다
   - 주제 이름은 아는 사람 누구나 구독할 수 있으니 **길고 무작위로** (예: PC 에서 `python -c "import secrets;print('stockapp-'+secrets.token_urlsafe(12))"` 로 만든 값)
2. `backend/.env` 에 `NTFY_TOPIC=위에서 만든 이름` → 서버 다시 켜기
3. KIS 모의투자 주문 화면 상태 칸의 **알림 시험 보내기** → 휴대폰에 'StockApp 알림 시험' 이 오면 끝

| 알림 | 우선순위 |
|---|---|
| AI 주문 제안 N건 — 승인 대기 (종목·금액) | 높음 |
| **자동 손절 매도** (승인 없이 나간 매도) | 긴급 |
| **매수 자동 취소** (급변 — 이유 포함) · 자동 취소 실패 | 높음 · 긴급 |
| **매수 주문** (승인한 매수가 조건이 맞아 지정가로 나감) | 보통 |
| 목표가 도달 매도 제안 | 높음 |
| 체결 (종목·수량·평균가) | 보통 |
| 주문 안 보냄(안전장치) · KIS 주문 거부 · 결과 확인 필요 | 높음 |
| 주문 정지 (긴급 정지 · 하루 손실 한도) | 긴급 |

**알림을 누르면** 휴대폰 브라우저로 웹 화면 **KIS 모의투자 주문 → 그 주문 위치**(`/kis?order=번호`, 강조 표시)가 열립니다.
- 클라우드 서버는 따로 설정할 것 없음 — `deploy/.env` 의 `DOMAIN`(설치 때 만든 주소)을 씀 (`bash deploy/update.sh` 한 번 하면 적용)
- 다른 주소로 열고 싶으면 `backend/.env` 에 `NTFY_CLICK_URL=https://내주소` (뒤 경로는 무시하고 주소만 씀)
- 처음엔 브라우저가 접속 비밀번호(Caddy)·앱 로그인을 물을 수 있음 — 로그인하면 알림의 그 화면으로 돌아감. 로그인은 12시간 유지
- 휴대폰 폭에서는 표 대신 카드로 보이고, 자동 규칙·설정은 접혀 있음 (승인 버튼 줄은 화면 아래에 붙어 있음)
- 화면 상태 칸에 '알림을 누르면 주소…' 가 보이면 링크 설정 완료 (노란 '열 주소 없음' 이면 위 설정 확인)

선택: `NTFY_CLICK_URL`(알림을 누르면 열 사이트 주소), `NTFY_TOKEN`(주제를 예약·비공개로 했을 때), `NTFY_SERVER`(직접 띄운 ntfy 서버).
알림에는 토큰·계좌번호를 넣지 않습니다 (종목·수량·가격만). 승인은 알림이 아니라 앱에서 2단계 코드로만 됩니다.

## 2. 하루 흐름
| 시각 (한국) | 하는 일 |
|---|---|
| 15:45~ (장 마감 15분 뒤) | AI 모의투자와 같은 판단 함수로 **KIS 모의투자 계좌의 실제 잔고**를 놓고 판단 → 매수·매도 **제안** (승인 대기). 인증된 이메일이 있으면 알림 메일 |
| 저녁 아무 때 | 화면에서 제안을 골라 **2단계 코드 입력 → 승인** (여러 건을 한 번에) = '아래 조건 안에서 사도 된다'. 상태 '승인 — 조건 맞으면 주문' |
| 09:01 (개장 1분 뒤) | 승인된 **매도**를 시장가로 보냄 |
| 09:05~15:20 **5초마다** (실시간 감시) | 승인된 **매수**: 조건이 맞으면 **지정가**로 주문, 안 맞으면 기다림(이유가 화면에 보임) · **급변**이면 매수 자동 취소 · 보유 종목이 **손절가 이하면 바로 자동 매도** · 목표가 이상이면 매도 제안 |
| 장중 1분마다 | KIS 체결 내역과 맞춰 '체결'로 바꾸고 앱 기록(보유 수량·손절가·목표가)에 반영 |
| 장중 5분마다 | KIS 잔고로 손절·목표 한 번 더 확인 (실시간 가격을 못 받을 때 대비) · 하루 손실 확인 |
| 15:20~15:30 | 동시호가라 새 주문 안 보냄 |
| 다음 거래일 15:30 | 그때까지 승인·주문 안 된 제안은 **기한 지남** (오래된 판단으로 주문하지 않게) |

'지금 제안 만들기' 버튼은 확정된 마지막 종가로 바로 판단합니다 (몇 분 걸림, 제안만 하고 주문은 안 함).

## 2-1. 장중 실시간 감시 규칙 (기본값 — 화면 '안전장치 · 매매 규칙'에서 바꿈)
가격은 KIS 실시간 체결가(웹소켓)를 쓰고, 그게 없으면 KIS 현재가(REST)를 15초마다 받습니다. 가격을 못 받은 종목은 그동안 판단하지 않습니다 (화면에 '가격 못 받음 N').

| 상황 | 하는 일 | 설정 |
|---|---|---|
| 개장 직후 5분 | 매수 안 함 (가격이 크게 출렁임) | 고정 |
| 제안 때보다 **+3% 넘게** 비쌈 | 매수 **기다림** (쫓아가서 안 삼). 다시 내려오면 그때 삼 | 제안 뒤 가격 상승 허용 (%) |
| 코스피·코스닥 중 하나가 **−2% 이하** | 매수 **보류** (시장 전체가 빠짐). 지수를 못 받아도 기다림 | 지수 하락 → 매수 보류 (%) |
| VI(변동성 완화장치)·거래 정지 | 매수 기다림 (주문 직전 KIS 현재가로 확인) | 고정 |
| 다 괜찮음 | **지정가** = 현재가 + 0.3% (호가 단위로 올림)로 매수 — 정한 가격보다 비싸게 안 삼 | 매수 지정가 여유 (%) |
| 제안 때보다 **−6% 넘게** 하락 (허용의 2배) | 매수 **자동 취소** (판단 때와 상황이 다름) | 제안 뒤 가격 상승 허용 × 2 |
| **10분 안에 −3% 넘게** 급락 | 매수 **자동 취소** — 승인 대기·조건 대기·이미 접수된(안 체결) 주문 모두 (접수된 건 KIS 에 취소 요청) | 10분 급락 → 매수 취소 (%) |
| 보유 종목 **손절가 이하** | 승인 없이 바로 **시장가 매도** (긴급 정지 중엔 안 함, 하루 손실 한도 정지 중엔 함). 안 나가면 2분 뒤 다시, 하루 3번까지 | 손절 % |
| 보유 종목 목표가 이상 | 매도 **제안** (승인해야 팔림 — 급하지 않아서). 거절하면 그날은 다시 안 물음 | 익절(목표) % |

지정가를 KIS 에 미리 걸어 두지 않고 앱이 조건을 보다가 보냅니다 — 앱(서버)이 꺼져 있으면 '안 사는 쪽'으로 끝나서, 급락 중에 걸어 둔 주문이 체결되는 일이 없습니다.
(손절은 서버가 켜져 있어야 동작합니다 — 서버가 꺼져 있으면 KIS 앱에서 직접 확인)

**검증**: AI 모의투자 '과거 시뮬레이션'에 **급변 보호** 옵션(기본 켬)이 있습니다 — 일봉으로 근사해서 '시가가 +3% 넘게 출발하면 그날 저가가 +3% 까지 내려올 때만 그 값에 삼,
−6% 넘게 출발하면 안 삼'. 옵션을 켜고/끄고 같은 기간을 돌려 비교하세요 (결과에 '안 산 매수·기다렸다 산 매수' 건수가 나옴).
10분 급락·VI·지수 보류는 일봉으로 알 수 없어 시뮬레이션에 없습니다. 손절은 원래부터 시뮬레이션에 들어 있습니다 (그날 저가가 손절가 아래면 손절가에 팖).

## 3. 안전장치
- **관리자만** (화면·서버 둘 다), **승인할 때마다 2단계 코드** (같은 코드 재사용 불가). 2단계를 안 켠 관리자는 승인 불가
- **1회 매수 한도**(기본 200만 원) — AI 가 더 큰 금액을 제안해도 한도까지만 삼
- **하루 주문 횟수**(기본 10건) — 자동 손절은 이 한도에 안 막힘
- **하루 손실 한도**(기본 50만 원, KIS 전날 총자산 대비) — 넘으면 **자동 정지** (새 매수 안 함, 걸려 있는 매수 취소, **손절 자동 매도는 계속**)
- **가격 확인**: 위 2-1 (비싸면 기다림, 급변이면 취소). 매도는 위험을 줄이는 주문이라 가격 확인 안 함
- **두 번 주문 방지**: 한 제안은 한 번만 승인됨 · 같은 종목에 접수 중인 주문이 있거나 오늘 같은 방향으로 이미 체결됐으면 안 보냄 ·
  주문을 보내기 전에 '보내는 중'으로 먼저 저장 → 그 사이 서버가 꺼지거나, 주문을 보낸 뒤 KIS 응답을 못 받으면(시간 초과·연결 끊김)
  다시 보내지 않고 **결과 모름**으로 표시 + 휴대폰 알림 (KIS 앱에서 확인). 그날 같은 종목 주문은 막음. 연결 자체가 안 됐으면 '주문은 안 들어감'으로 표시
- **잔고 대조**: 앱이 체결시킨 수량과 KIS 잔고가 다르면 매수 안 함. HTS·KIS 앱에서 직접 사고팔았다면 **기준 다시 맞추기**
  (주문은 안 나가고 앱 기록만 바꾸므로 2단계 코드 없이 확인 창만). 앱이 보낸 주문이 체결되는 중이라 다른 것은 '(체결 중)'으로 표시되고 1분 안에 저절로 맞춰짐 — 이때는 누를 필요 없음.
  비교 전에 체결 내역을 먼저 앱 기록에 반영하고, 기준 맞추기 때는 이미 잔고에 들어간 체결을 '반영됨'으로 표시해 나중에 두 번 더하지 않음
- **긴급 정지** 버튼: 2단계 코드 없이 바로 — 승인 대기·대기 주문 취소 + 접수된(안 체결) 주문 KIS 취소 요청 + **자동 손절도 멈춤**. **다시 시작**은 2단계 코드
- **취소와 일부 체결**: 취소하기 전에 그때까지 들어온 체결을 먼저 기록하고, 취소가 KIS 체결 내역에 반영되면 '취소'(일부 체결됐으면 '일부 체결' — 산 만큼은 보유로 남음)
- **감사 로그**: 제안·승인·거절·주문·체결·막힘·정지·설정 변경을 누가 언제 했는지 모두 남김 (지우지 않음)
- 설정(한도·매매 규칙) 변경도 2단계 코드

## 4. 주문 상태
승인 대기 → 승인(조건 맞으면 주문 — 기다리는 이유가 메모에 나옴) → 보내는 중 → 주문 접수 → 체결 / 일부 체결 / 안 체결.
'자동 손절' 표시가 붙은 매도는 승인 없이 나간 주문입니다.
그 밖에: 거절(내가) · 기한 지남 · 취소 · **안전장치로 안 보냄**(이유가 메모에 나옴) · **KIS 거부**(KIS 가 돌려준 문구) · **결과 모름**(KIS 앱에서 확인).

## 5. 문제 해결
- 화면에 'KIS 모의투자 연결 필요' — `.env` 세 줄을 넣고 서버를 다시 켰는지 확인
- '잔고를 못 받음' — 모의투자 앱키가 모의투자용인지(실전용 키는 모의 서버에서 안 됨), 계좌번호가 모의투자 계좌인지 확인
- **'INVALID_CHECK_ACNO'** (계좌번호 확인 실패) — 모의투자 서버가 계좌번호를 거부한 것입니다. 화면 상태 줄의 '계좌 ****1234-01 (.env …)' 로 어떤 값을 쓰는지 봅니다.
  - `(.env KIS_ACCOUNT_NO)` 로 나오면: `KIS_MOCK_*` 세 줄이 비어 있어(또는 하나라도 비어 있어) 시세용 **실전 계좌번호**를 쓰는 중 → 세 줄을 모두 넣고 서버 다시 켜기
  - `(.env KIS_MOCK_ACCOUNT_NO)` 로 나오면: ① 그 번호가 **모의투자 계좌번호**인지 (한국투자 앱 → 모의투자 메뉴에서 확인, 실전 계좌번호와 다름)
    ② `KIS_MOCK_APP_KEY` 를 KIS Developers 에서 **그 모의투자 계좌로** 발급받았는지 (앱 신청 때 고른 계좌와 같아야 함 — 다르면 앱키를 그 계좌로 다시 신청)
    ③ 끝 2자리(상품코드)가 맞는지 (보통 `01`) ④ 모의투자 신청 기간(보통 3개월)이 끝나지 않았는지
- 'KIS 잔고와 앱 기록이 다릅니다' — '(체결 중)'이면 기다리면 됨. 직접 거래했으면 기준 다시 맞추기, 모르는 거래면 먼저 긴급 정지 후 KIS 앱에서 확인
- 보유 종목이 20개 이상이면 잔고를 끝까지 못 읽어 대조를 멈춤 (최대 보유 종목 수 기본 5)

## 6. 아직 실제로 확인 못 한 것 (실서버 미검증)
이 개발 환경에서는 KIS 서버에 접속할 수 없어서, KIS 응답 형식을 흉내 낸 가짜 서버로만 확인했습니다.
- 지정가 매수(`ORD_DVSN=00`, `ORD_UNPR`=호가 단위로 맞춘 가격) — 모의투자 서버가 지정가를 받는지, 취소 뒤 체결 내역의 `rmn_qty`·`cncl_cfrm_qty` 값
- VI 여부: KIS 현재가(`FHKST01010100`)의 `vi_cls_code`(N 이 아니면 발동 중으로 봄)·`temp_stop_yn` — 실제 VI 때 값 확인 필요
- 장중 실시간 감시 가격: 웹소켓이 안 되면 REST 멀티종목 시세(15초)로 동작 — 화면 상태 줄 '실시간 체결가 N · REST N' 으로 확인
- 주문 TR: 매수 `VTTC0012U`·매도 `VTTC0011U`(새 번호, 안 되면 예전 `VTTC0802U`·`VTTC0801U`), 취소 `VTTC0013U`(`VTTC0803U`), 잔고 `VTTC8434R`, 체결 `VTTC0081R`(`VTTC8001R`)
- 잔고 필드(`prvs_rcdl_excc_amt` D+2 예수금, `bfdy_tot_asst_evlu_amt` 전날 총자산)와 체결 필드(`tot_ccld_qty`, `avg_prvs`)
- 처음 연결하면 화면의 잔고가 KIS 앱과 같은지, 소량(1주) 주문 하나로 승인 → 접수 → 체결까지 확인해 주세요. 다르면 화면·감사 로그를 캡처해서 알려 주세요.
